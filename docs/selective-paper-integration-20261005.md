# 선택형 국내 단타: 모의 엔진 연결 검증

## 범위

- `paper_selective_breakout`: 상승 추세, RSI 상승, 거래량 증가, 이전 20봉 고점 돌파.
- `paper_selective_pullback`: 같은 필터와 EMA20 재돌파.
- 모의 전략 목록에만 노출. LIVE 실행, 강제청산, OFF, 정규장 외 실행 차단.
- 확정 5분봉만 사용. 과거/중복/역순/비정상 가격 데이터는 주문 근거로 사용하지 않음.
- 종목 배정 예산의 30%, 추가 물타기 없음, 종목당 하루 한 번 신규 진입.
- 비용 가정 반영 -1% 손절 / +2.5% 목표 / 90분 제한 / 15:15 이후 청산 신호.
- 전략의 체결 수량과 실제 엔진 보유 수량이 다르면 개인 보유 보호를 위해 HOLD.
- 기존 KIS 주문·미체결·거래이력 경로 사용. 부분체결은 잔여 주문 추적 유지.

## 실제 검증 결과

`python -m unittest discover -s tests -q`: **334개 통과**.

추가 13개 테스트는 확정 분봉, 유효성·신선도, 예산, 하루 진입 횟수,
매도 조건, 개인 보유 보호, LIVE/OFF/강제 실행 차단, 실제 엔진 함수 연결,
모의 브로커 대역으로 부분 매수·매도 접수 이후 pending 유지 등을 확인했다.
기존 취소·부분체결 복구 및 FIFO 이력 테스트도 함께 통과했다.
이는 오프라인 테스트이며 KIS 모의 서버의 실제 체결 확인과 다르다.

## KIS 모의 서버 직접 조회 — 1791 계좌 확인 후

사용자가 모의 계좌 끝 4자리 `1791`을 확인했다. 일치하는 사용자 범위 계좌는 1개이며,
KIS 모의 호스트와 모의 자격증명 사용을 확인했다.

- 최초 캐시 인증 전용 검사: 유효한 저장 토큰 없음.
- 모의 OAuth 1회 갱신 후 국내 잔고 조회 성공: 보유 종목 0개.
- 당일 국내 체결 조회 성공: 0건.
- 실투자 요청 및 매매 주문 제출: 0건.
- 인증 토큰은 검증 프로세스 메모리에만 보관했으며 계좌 설정이나 ON/OFF는 변경하지 않았다.

`scripts/verify-selective-paper-readonly.py --account-last4 1791 --refresh-auth`
실행 결과는 `data/reconciliation-audits/selective-paper-readonly-latest.json`에 저장했다.
`--refresh-auth`는 모의 OAuth만 허용하며 모든 매매 POST 요청은 여전히 차단한다.

## 남아 있는 외부 확인

읽기 전용 KIS 검증 도구가 모의 DB에서 사용자 범위 계좌 2개를 발견했다.
사용할 계좌를 추측하지 않고 외부 API 호출 전에 중단했던 상태는 위 확인으로 해소됐다.
사용자가 모의 계좌번호 끝 4자리(상품코드 제외)를 확인하면
`scripts/verify-selective-paper-readonly.py --account-last4 NNNN`으로 한 계좌를 특정한다.
기본은 캐시 인증만 허용하며 `--refresh-auth`를 명시해야 모의 인증을 갱신한다.

실제 KIS 접수·체결·취소·결제 확인은 완료로 표시하지 않는다.
자동매매 ON/OFF와 계좌 데이터는 변경하지 않았다.

## 성능 해석

기존 연구 결과(`selective-daytrade-review-20261004.md`)는 두 후보 모두
실투자 배포 기준 미달이었다. 이 연결 작업은 수익성 승인이나 수익 보장이 아니다.
같은 과거 표본을 재사용한 결과를 독립적인 검증 성과로 제시하지 않는다.
실행에서는 다음 봉 시가 체결을 보장하지 않으며, 실제 슬리피지와 지연을 기록해
연구 가정과 차이를 비교해야 한다. 분봉 공급이 끊기면 이 전략은 HOLD하며,
서버 감시형 청산은 증권사에 미리 접수된 손절 주문이 아니다.
