# PAPER 실행기 수정 및 검증 범위

## 수정

- 화면 ON과 달리 PAPER 백그라운드 스레드에는 Flask 로그인 문맥이 없어 관리자 검사에서 국장/미장이 모두 비활성 처리됐다.
- 인증된 사용자만 실행기를 시작하고, 메인 실행기와 후보탐색·체결대조·LOC 하위 스레드에 동일 소유자 문맥을 전달한다.
- PAPER 실행기 상태를 사용자별로 분리하고 대시보드에 실제 PAPER 결과를 전달한다. LIVE 동의 정책이나 ON/OFF는 변경하지 않았다.
- KIS 모의 해외 예약 API 호출과 해외 LOC 주문을 네트워크 호출 전에 명시적으로 거절한다. 일반 체결 조회에서 지원하지 않는 예약조회 보충 호출은 생략한다. 실패를 빈 예약 목록으로 해석하지 않는다.

## 관측 및 검증

- 수정 전 PAPER 상태: daytrade_feature_enabled=false, enabled=false, us_enabled=false.
- 수정 후 세 값 true, 국장 후보 탐색 실행 및 청산 감시 완료, 미국 시장 종료 시 대기 응답 확인.
- 441개 자동 테스트 통과. 실제 Flask 자식 스레드와 중첩 스레드의 소유자 유지, 익명/삭제 사용자 차단, LIVE 콜백 무변경 포함.
- PAPER 설정 세 전략은 기존 ON을 유지한다. 이번 작업으로 LIVE 스위치를 변경하거나 LIVE 주문을 제출하지 않았다.

## 미완료와 환경 차이

- KIS 공식 해외 주문 예제는 모의 매수/매도에서 ORD_DVSN=00 지정가만 지원한다고 명시한다. LOC를 일반 지정가로 조용히 바꾸면 전략 의미가 달라진다.
- PAPER 무한매수 LOC와 예약의 실제 체결 검증은 완료가 아니다. 별도 모의 실행 방식과 그 한계 표시가 필요하다. 기존 PAPER SOXL 사이클도 추가설정 상태이며 실전 사이클을 복사하지 않는다.
- 자동 테스트 통과는 실제 주문·부분체결·취소·결제 및 수익성 검증 완료를 뜻하지 않는다.
- 30분 간격 후속 점검을 등록했다. 상태 불변 시 알림 없이, 오류/조치/검증 결과가 생길 때 보고한다.

공식 근거: https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/order/order.py

## 16시 후속 점검

- 모의 계좌 읽기 전용 재조회: 국내 잔고 0종목, 오늘 국내 체결 0건, 해외 잔고 1종목, 해외 주문내역 0건. 모든 조회 성공, 접수한 주문은 0건이다. 로컬 주문 로그를 오늘 실제 체결로 간주하지 않는다.
- 미지원 예약을 실행기에서 매번 재시도하고 로그를 쌓던 경로를 `unsupported` 상태로 분리했다. 설정 ON은 유지하지만 접수/검증 성공으로 표시하지 않는다. 단타 및 체결 대조 루프는 유지한다.

### 16:31 후속 점검

실행기 외의 직접 호출 경로에서 예약 로그가 추가되는 것을 확인했다. `run_due_loc_automation` 공통 진입점에도 동일한 PAPER 기능 제한을 적용하여 API/스케줄러의 force·verify 호출도 미지원 예약 엔진으로 들어가지 않게 했다. 기존 LIVE 예약 재시도 회귀 테스트는 LIVE 모드를 명시하고, PAPER 강제 호출 차단 테스트를 추가했다. 전체 443개 테스트 통과.
