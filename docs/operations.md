# 운영·배포·재학습 점검

기준: 2026-10-08. 일반 개발 검증에서는 실제 주문·취소·잠금 해제·자동매매 ON을 실행하지 않습니다. 기존 ON 상태를 재개할 수 있는 서버 재시작도 영향 확인 후 수행합니다.

## 수정했는데 화면이 그대로일 때

1. 브라우저 주소와 연결된 LIVE/PAPER 계정을 확인합니다. `localhost`와 `127.0.0.1`은 인증 저장 공간이 달라질 수 있으므로 무심코 섞지 않습니다.
2. 실행 프로세스의 포트·프로젝트 경로를 확인합니다. 현재 Windows 런처 기본 포트는 LIVE 3001, PAPER 3002입니다.
3. 원본 `src`, 빌드된 `build/src`, 실행용 `bundle/src`와 `bundle/www`를 구분합니다. 원본 diff만으로 배포 완료라고 판단하지 않습니다.
4. 기존 WIZ 런타임을 지정하여 `scripts/rebuild-stock8-frontend.ps1`을 실행합니다. 기본 경로는 해당 개발 PC의 `C:\stock8-runtime2\app`이며 다른 PC에서는 맞춰야 합니다.
5. `bundle/.stock8-build-stamp`와 새로운 산출물을 확인합니다. 빌드 스크립트는 WIZ 종료 코드 외에 산출물의 생성 시각·크기도 검사합니다.
6. Python 실행 코드 변경이면 현재 학습/주문 작업과 저장된 운용 상태를 확인한 후 해당 프로세스의 재시작이 필요한지 판단합니다. 무관한 서버를 종료하지 않습니다.
7. 브라우저에서 실제 표시, API 응답의 갱신 시각, 서버 상태를 함께 확인합니다. “빌드 성공”과 “사용자 화면 검증 완료”를 별도로 기록합니다.

문서만 변경했다면 프런트엔드 빌드나 운영 서버 재시작은 필요하지 않습니다.

## 재학습 완료 판정

- 관리자 국내 단타의 전체 종목 재훈련은 선택한 전략을 입력으로 보낼 수 있습니다. 전체 전략 비교와 같은 의미로 취급하지 않습니다.
- 버튼 클릭 전후 계정별 `recommendation.json` 생성 시각을 비교합니다. `training_skipped`, 데이터 `errors`, 평가 수, `trade_ready_count`, `quality_guard`를 확인합니다.
- 화면 실패 메시지만으로 서버 작업이 종료됐다고 판단하지 않습니다. 현재 동기 추천 요청은 AJAX 60초 제한보다 오래 실행될 수 있습니다.
- 타임아웃 후에는 산출물·서버 로그를 먼저 확인하고 중복 재훈련 요청을 피합니다. 작업 ID/진행 조회 방식으로 바꾸는 것은 미완료 개선 항목입니다.
- 자동 생성 개별 `optimization-report.md`와 전체 추천 JSON은 서로 다른 범위입니다.
- 후보 0개 통과는 학습 파일 미생성과 다릅니다. 진입 기준을 낮추거나 실제 주문을 보내는 방식으로 학습 성공을 증명하지 않습니다.

## 손익 조회가 느릴 때

1. 최초 조회인지, 계정/기간 변경인지, 저장값이 있는 반복 조회인지 구분합니다.
2. 계좌 범위 DB 캐시와 화면의 마지막 갱신 시각을 확인합니다. 과거 6시간/오늘 30초 TTL은 외부 응답 지연과 다릅니다.
3. 백그라운드 집계의 브로커 동기화 성공 여부, 전체 체결 페이지 조회, 오류를 확인합니다.
4. 실패를 실현손익 0으로 덮어쓰거나 다른 계좌 캐시로 대체하지 않습니다.
5. 과거에도 체결 정정·지연 반영이 가능하므로 무기한 고정 집계로 바꾸지 않습니다.

## RUNNING인데 거래가 없을 때

RUNNING은 워커 생존 표시입니다. 다음 조건을 순서대로 분리해서 확인합니다.

1. 계정/관리자 권한, 해당 시장 스위치, 실투자 동의.
2. 현재 주문 세션과 브로커 연결·조회 결과의 최신성.
3. 종목 잠금 및 무한매수/단타 소유권 충돌.
4. 주문가능 현금, 미체결 점유, 무한매수 확보금, 요청 시드.
5. 후보 데이터 최신성, 품질 기준, 실제 진입 신호.
6. 브로커 접수와 체결 결과 — 화면 신호를 체결로 표시하지 않음.

보호된 종목이나 무한매수 자산을 단타 재원으로 임의 매도하지 않습니다. 조회 실패와 현금 0을 구분해야 하며, 불완전한 주문 조회 후 중복 주문을 보내면 안 됩니다.

## Git 반영 체크리스트

- 회귀 테스트: `.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -q`
- 변경 문서 링크·명령·구현 설명 일치 확인.
- `git diff --check` 및 staged diff 검토.
- API 키·토큰·계좌번호·개인 잔고·원장·스크린샷·로컬 감사 보고서 제외.
- 파일 경로를 지정하여 stage; 운영 DB와 자동 생성 실행 로그를 `git add .`로 일괄 포함하지 않음.
- 현재 작업 브랜치에 커밋·push 후 원격 HEAD와 비교. 강제 push하지 않음.

테스트 통과 수, 배포 여부, 실제 브라우저 확인 여부, 실계좌 시나리오 검증 여부를 각각 별도로 보고합니다.
