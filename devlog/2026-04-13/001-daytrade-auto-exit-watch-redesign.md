# 단타 자동청산 감시·방어선 우선순위 재설계

- **ID**: 001
- **날짜**: 2026-04-13
- **유형**: 기능 추가 + 리스크 제어 개선

## 작업 요약
단타 포지션의 판매가/손절가가 단순 표시값에 머무르지 않도록, 스케줄러 기반 자동청산 감시 흐름을 별도 체계로 분리했다. 활성 포지션은 자동순환이 꺼져 있어도 청산 감시를 받을 수 있게 했고, 청산 계열 신호는 급변장/쿨다운 같은 가드레일에서 신규 매수보다 우선 처리되도록 조정했다.

## 변경 파일 목록
- `src/portal/trading/model/struct/daytrade_engine.py`
  - 자동청산 감시 메타데이터(`last_exit_watch_at`, `last_exit_action` 등) 추가
  - `execute_exit_watch()` 추가로 활성 포지션 청산 전용 감시 루프 구현
  - 청산 신호에 대해 쿨다운/급변장 차단을 경고 수준으로 완화
  - 판매가/손절가 가격을 100원 단위로 정규화해 저장
- `src/portal/trading/route/scheduler/controller.py`
  - `run_daytrade_exit_watch()` 추가
  - 스케줄러가 단타 자동순환과 별개로 자동청산 감시를 항상 실행할 수 있게 확장
- `src/app/page.daytrade/api.py`
  - 차트 응답의 매매 계획에 `auto_exit` 상태 포함
- `.github/custom/daytrade-usage.md`
  - 자동청산이 브로커 예약주문이 아닌 스케줄러 감시형 구조임을 운영 문서에 반영

## 비고
- 국내 단타 청산은 현재 KIS 브로커 서버 예약주문이 아니라, 스케줄러가 시세를 주기적으로 확인해 시장가 청산을 넣는 구조다.
- 따라서 실제 반응 속도는 스케줄러 호출 주기에 영향을 받는다.
