# too many open files 원인 분석 및 워커 누수 수정

- **ID**: 001
- **날짜**: 2026-04-20
- **유형**: 버그 수정

## 작업 요약

- `too many open files` 오류의 직접 원인을 추적한 결과, 단타 자동매매 백그라운드 워커가 코드 리로드 때 중복 생성되며 종료되지 않아 스레드와 파일 디스크립터가 누적되고 있었음.
- 누적된 워커 스레드가 `yfinance` 캐시 DB(`cookies.db`, `tkr-tz.db`)와 소켓을 반복적으로 붙잡으면서 FD가 1024개까지 증가했고, 결국 `EMFILE` 상태에 도달함.
- 워커 관리를 프로세스 전역 단일 상태 방식으로 변경하고, 누수된 forkserver 자식 프로세스를 정리하여 즉시 FD를 회수함.

## 변경 파일 목록

### 1. 워커 싱글톤/세대 관리 개선
- `src/portal/trading/model/struct.py`
  - 코드 리로드 후에도 공유되는 프로세스 전역 상태(`sys` 기반) 추가
  - 워커 세대(`generation`) 기반으로 최신 워커만 유지하도록 수정
  - 기존 `stop_flag` 경쟁 조건 제거
  - `worker_status()`가 전역 상태를 기준으로 현재 워커를 정확히 보고하도록 수정
  - 설정 변경 시 강제 실행 플래그도 전역 상태에 즉시 반영하도록 수정

## 검증 내용

- 누수 발생 시점 프로세스 확인
  - 스레드 수: 164
  - FD 수: 1024
  - 스레드 이름: `trading-daytrade-worker` 다수 중복
  - 열린 FD 다수: `yfinance` 캐시 DB / socket
- 수정 후 빌드 성공
- 번들 반영 및 `.pyc` 정리 완료
- 누수된 forkserver 자식 프로세스 종료 후 신규 자식 상태 확인
  - 스레드 수: 1
  - FD 수: 10

## 결론

- 원인은 파일 `open()` 미종료가 아니라, **코드 리로드 때 종료되지 않는 백그라운드 워커 스레드 누수**였음.
- 수정 후 동일 유형의 워커 중복 생성이 재발하지 않도록 구조를 보완했고, 현재 누적된 FD도 함께 정리함.
