# 단타 자동매도 메커니즘 점검 및 KIS 잔고 캐시 수정

- **ID**: 003
- **날짜**: 2026-04-16
- **유형**: 버그 수정

## 작업 요약
단타 자동매도 경로를 실제 보유 종목 기준으로 추적해 판매 시그널 생성, 주문 실행, 브로커 잔고 반영 흐름을 재검증했다.
문제는 단일 원인이 아니라, 브로커 보유 동기화 누락 이후에도 주문 직후 KIS 잔고 캐시가 남아 이미 매도된 종목을 계속 보유 중으로 오인하면서 `주문 가능한 수량을 초과했습니다` 오류를 반복한 데 있었다. 백그라운드 워커 재시작 경로와 자동청산 감시 실행도 함께 보강했다.

## 변경 파일 목록
### 엔진/워커
- `src/portal/trading/model/struct.py`
  - 죽은 단타 워커 스레드가 남긴 플래그를 초기화하고 자동 재시작 가능하도록 수정
  - 워커 시작 시 즉시 1회 실행되도록 강제 플래그 설정
  - 백그라운드 워커가 `auto_cycle` 뿐 아니라 `execute_exit_watch()`도 함께 실행하도록 확장
  - `worker_status()`에 `alive` 상태 추가

- `src/portal/trading/model/struct/daytrade_engine.py`
  - 기존 미체결 매도 주문 취소 헬퍼 추가
  - 자동매도 주문을 체결 우선의 시장가로 통일
  - 주문 성공/취소 직후 KIS 잔고 캐시를 즉시 무효화하도록 수정
  - 수동 즉시 매도와 사전예약 매도 성공 시에도 잔고 캐시를 즉시 갱신

### KIS API
- `src/portal/trading/model/struct/kis_api.py`
  - `get_domestic_fills_today()`가 첫 페이지만 읽던 문제를 수정하고 연속 페이지를 순회하도록 보강

## 검증
- `036570` NC 종목은 판매 시그널이 `SELL_FULL`로 정상 계산됨을 재확인
- 자동 실행 후 실제 활성 보유 종목 목록에서 `036570`, `011780`, `015760`이 제거되고 잔여 보유만 남는 것을 확인
- 브로커 원본 잔고 기준으로 NC는 `thdt_sll_qty=2`, `hldg_qty=0`, `ord_psbl_qty=0` 상태였고, 이는 이미 당일 매도가 반영됐는데 캐시 때문에 재매도 오류가 반복됐음을 의미함
- 클린 빌드 성공
