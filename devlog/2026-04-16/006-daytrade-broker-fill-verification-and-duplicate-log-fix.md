# 단타 실체결 검증 및 중복 거래일지 정리

- **ID**: 006
- **날짜**: 2026-04-16
- **유형**: 버그 수정

## 작업 요약
당일 거래일지가 state 복원 로그와 실제 체결 로그를 함께 세면서 매도 1회가 2회처럼 보이던 문제를 정리했다.
거래일지 집계 시 KIS 당일 체결 내역을 우선 기준으로 사용하고, 브로커 체결이 확인되지 않은 synthetic 복원 로그는 집계에서 제외하거나 별도 경고 영역으로 분리해 실제 거래 기준으로 확인할 수 있게 했다.

## 변경 파일 목록
### 백엔드
- `src/portal/trading/model/struct/daytrade_engine.py`
  - `daily_trade_summary()`가 KIS 당일 체결을 조회해 `order_no + side` 기준으로 로그를 검증하도록 수정
  - 실체결이 확인된 synthetic 로그만 복원 대상으로 허용하고, 미검증 복원 로그는 집계에서 제외
  - 실체결 검증/복원/로컬 로그 카운트와 제외된 복원 로그 목록을 응답에 추가
  - 브로커 체결 가격·수량을 우선 사용해 FIFO 손익 계산 근거를 실제 체결 기준으로 보정

### 프론트엔드
- `src/app/page.daytrade/view.pug`
  - 거래 로그 상단에 검증 상태 요약(실체결 검증/복원/로컬/제외)을 추가
  - 각 로그 행에 검증 상태 배지를 표시
  - 집계에서 제외된 복원 로그를 별도 경고 박스로 노출
