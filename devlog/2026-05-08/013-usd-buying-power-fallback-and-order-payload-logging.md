# USD 주문가능금액 fallback 및 해외주식 주문 payload 로깅 추가

- **ID**: 013
- **날짜**: 2026-05-08
- **유형**: 버그 수정

## 작업 요약
대시보드의 `달러 주문 가능액 동기화 실패`가 `inquire-psamount` 전용 API 실패만으로 즉시 에러 처리되던 문제를 완화했다.
해당 API 실패 시 해외잔고 조회의 `cash_balance`를 fallback으로 사용하도록 변경해 대시보드와 엔진이 0으로 붕괴하지 않게 했다.
또한 실제 해외 매수 주문 직전 payload 핵심 필드(`PDNO`, `OVRS_EXCG_CD`, `ORD_QTY`, `OVRS_ORD_UNPR`)를 로그로 남기도록 추가했다.

## 원문 요청사항
```text
1. 달러 잔고 동기화 실패 오류 해결
즉 문제는 API 기능 미제공/락보다는 아래 쪽일 가능성이 훨씬 커.

현재 상황 해석

이미지에 있는 항목 중 미장 거래에 필요한 건 보통 이거야.

[해외주식] 주문/계좌
[해외주식] 기본시세
[해외주식] 실시간시세
[해외주식] 시세분석

미국주식 주문은 여기서 [해외주식] 주문/계좌 쪽을 써야 해.
그래서 API 그룹이 없어서 주문이 막히는 상황은 아닌 듯해.

“주문가능금액을 초과했습니다”가 뜨는 진짜 가능성
1. 해외주식 매수가능금액을 안 보고 있음

국내주식 주문가능금액이 아니라, 해외주식 전용 조회를 해야 해.

확인해야 하는 API는 대충 이런 쪽이야.

[해외주식] 주문/계좌 > 해외주식 매수가능금액조회
[해외주식] 주문/계좌 > 해외주식 잔고
[해외주식] 주문/계좌 > 해외증거금 통화별조회

여기서 USD 주문가능금액이 0이거나 부족하면 주문이 거절돼.

2. 원화는 있는데 달러가 없음

국장에서는 원화 예수금으로 바로 주문되지만, 미장은 보통 달러 기준으로 계산돼.

예를 들어 계좌에 원화 100만 원이 있어도, 해외주식 API에서 USD 주문가능금액이 0이면:

주문가능금액 초과

이렇게 뜰 수 있어.

MTS에서는 자동환전/통합증거금으로 되는 것처럼 보여도, API에서는 별도 계산값을 요구할 수 있음.

3. 주문가격을 원화로 넣었을 가능성

이거 진짜 많이 하는 실수야.

미국주식 주문가격은 달러 가격으로 넣어야 해.

예를 들어 AAPL 1주를 200달러에 산다면:

{
  "PDNO": "AAPL",
  "OVRS_EXCG_CD": "NASD",
  "ORD_QTY": "1",
  "OVRS_ORD_UNPR": "200.00"
}

이런 식이어야 하는데, 만약 원화 환산 가격으로:

{
  "OVRS_ORD_UNPR": "280000"
}

이렇게 보내면 API는 280,000달러짜리 주문으로 인식할 수 있어.
그러면 당연히 주문가능금액 초과가 뜸.

4. 해외주식 주문 API인데 국내주식 계산 로직을 재사용 중

국장 주문이 잘 된다고 해서 그 로직 그대로 미장에 쓰면 안 돼.

미장은 보통 이런 값들이 다르게 들어가야 해.

구분	국내주식	해외주식
주문 API	국내주식 주문	해외주식 주문
시장코드	KRX 등	NASD, NYSE, AMEX
주문가격	원화	달러
주문가능금액	원화 예수금	USD 매수가능금액
종목코드	005930	AAPL, TSLA 등
지금 바로 확인할 것

먼저 코드에서 주문 넣기 직전에 아래 4개를 로그로 찍어봐.

1. 종목코드: PDNO
2. 거래소코드: OVRS_EXCG_CD
3. 주문수량: ORD_QTY
4. 주문단가: OVRS_ORD_UNPR

예를 들어 애플 1주 주문이면 이런 식이어야 정상에 가까워.

PDNO = AAPL
OVRS_EXCG_CD = NASD
ORD_QTY = 1
OVRS_ORD_UNPR = 200.00 근처

근데 주문단가가 200000, 280000, 300000 이런 식이면 원화 가격을 넣고 있는 문제야.

결론

저 화면 때문에 안 되는 건 아니고, 오히려 해외주식 주문 API는 사용 가능한 상태로 보여.

지금 에러는 거의 이쪽이야.

1. USD 주문가능금액이 부족함
2. 원화 예수금만 보고 주문 넣음
3. 해외주식 매수가능금액조회 API를 안 씀
4. 주문가격을 달러가 아니라 원화로 넣음
5. 국내주식 주문 로직을 해외주식에 그대로 재사용함

제일 먼저 해외주식 매수가능금액조회 결과랑 실제 주문 payload를 확인해야 해.
특히 OVRS_ORD_UNPR 값이 달러인지 원화인지부터 봐.
```

## 변경 파일 목록

### `src/portal/trading/model/struct/kis_api.py`
- `get_buying_power_info()`
  - `inquire-psamount` 실패 시 `get_balance().cash_balance`를 fallback으로 사용
  - fallback 성공 시 `ok=True`, `source="balance.cash_balance"`로 반환
  - 가격이 있을 경우 `qty`를 보수적으로 `99%` 기준으로 계산
  - 실패 원인과 fallback 실패 원인을 경고 로그로 남김
- `buy_order()`
  - 주문 직전 `PDNO`, `OVRS_EXCG_CD`, `ORD_QTY`, `OVRS_ORD_UNPR`, `ORD_DVSN`을 로그로 남기도록 추가

## 분석 메모
- 현재 코드상 해외 주문은 이미 `/uapi/overseas-stock/v1/trading/order`를 사용하고 있음
- 주문 payload도 `PDNO`, `OVRS_EXCG_CD`, `ORD_QTY`, `OVRS_ORD_UNPR`로 구성되어 있어 구조상 국내주식 주문 API 재사용 문제는 아님
- 주문 단가도 `buy_order(symbol, qty, price=...)`에 전달된 USD 가격을 그대로 사용하고 있어, 코드 기준으로는 원화 가격을 넣는 구조는 아님
- 실제 장애는 `해외주식 매수가능금액조회` 응답 실패 시 화면과 엔진이 곧바로 0/실패로 해석하던 경로에 더 가까웠음
