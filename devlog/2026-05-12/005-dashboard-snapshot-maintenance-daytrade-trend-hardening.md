# 대시보드 연결 유지·일일 스냅샷 고정·야간 정리 연결·단타 로딩/추세판단 보강

- **ID**: 005
- **날짜**: 2026-05-12
- **유형**: 버그 수정

## 작업 요약
대시보드 KIS 연결 상태가 일시 실패에 바로 끊어진 것으로 보이던 문제를 최근 성공 기반 grace로 완화했다.
자산추이용 `account_snapshot`가 같은 날짜에 계속 덮어써지던 구조를 1일 1회 저장으로 고정하고, 야간 DB 정리 작업이 실제 스케줄러 경로에서 실행되도록 연결했다. 국장 단타 초기 로딩에서는 불필요한 시세 재조회 비용을 줄였고, 추천 랭킹에는 현재 차트의 추세 정합도 점수를 반영해 하방 우세 종목을 더 잘 거르도록 보강했다.

## 원문 요청사항
```text
1. 아니 대시보드 시스템 연결은 왜 자꾸 끊어지는거야? 계{속 유지해
2. 자산추이는 항상 개판이야.하루에 한번만 제대로 찍어서 저장하면 되는걸 왜 못하는건데
3. 거래 로그 매일 밤에 지워서 용량 확보한다고 했는데 실제로 진행되고있지 않은거 같아. 검토 진행해봐
4. 단타 페이지들은 왜이렇게 로딩이 오래 걸리는건데 이유를 설명하고 제발 최적화 진행해
5. 훈련할때 그래프 제대로 분석해서 오를건지 하락할건지 파악 좀 해봐
```

## 변경 파일 목록

### 대시보드/연결 상태
- `src/app/page.dashboard/api.py`
  - 최근 성공한 KIS 연결 결과를 짧은 grace 기간 동안 유지하는 sticky 상태를 추가해 일시적인 테스트 실패로 UI 연결이 바로 끊어지지 않게 조정.

### 자산 스냅샷/스케줄러 유지보수
- `src/portal/trading/model/struct/engine.py`
  - 엔진 자동 스냅샷이 같은 날짜 row를 반복 upsert하지 않고, 이미 저장된 날짜면 건너뛰도록 변경.
- `src/portal/trading/route/scheduler/controller.py`
  - 스케줄러 요청 경로에서 야간 `database_maintenance()`를 실제로 실행하도록 연결.
  - 유지보수 마지막 실행일/시각을 config에 기록.
  - 스냅샷 API는 수동 호출일 때만 강제 갱신하고, 자동 경로는 하루 1회만 저장.
- `src/portal/trading/model/scheduler.py`
  - 23:00을 놓쳐도 다음 호출 시 overdue maintenance를 보정 실행하도록 스케줄 판단식 수정.
  - 마지막 유지보수 실행 시각을 config에 영속화.

### 단타 로딩/훈련 추세판단
- `src/app/page.daytrade/api.py`
  - 부트스트랩에서 초기 active position 시세 재조회를 제거해 첫 렌더 비용을 축소.
- `src/portal/trading/model/struct/daytrade.py`
  - 현재 바 기준 `trend_alignment_score` / `regime` 계산 추가.
  - 전략별 최소 추세 정합도 기준을 도입.
  - 추천 랭킹 점수와 quality guard에 현재 차트 추세 정합도를 반영해 상승/하락 판별력을 보강.
