# 미장 단타 로딩 지연 완화 및 알고리즘 설명 추가

- **ID**: 013
- **날짜**: 2026-05-06
- **유형**: 기능 추가

## 작업 요약
미장 단타 페이지의 초기 로딩 병목이 `us_model_ranking()` 전체 백테스트와 `us_verify_runtime()`/`us_daily_log()` 동시 호출에 있다는 점을 확인하고, 화면은 먼저 표시한 뒤 무거운 검증·랭킹은 백그라운드/캐시 기반으로 불러오도록 변경했다.
또한 각 미장 매매 알고리즘의 요약·진입 규칙·청산 규칙을 화면에서 바로 볼 수 있도록 전략 설명 섹션을 추가했다.

## 원문 요청사항
```text
미장 단타 로딩 너무 오래 걸려. 어디서 막히는지 확인하고 고쳐. 불필요한 중복 파일 다 삭제하고 최적화도 진행해
미장 모델 승률 너무 안좋은거 아니야? 실제로 사용할 정도로 괜찮은지 검토해보고 결과 나한테 설명해봐
각 매매 알고리즘 설명을 볼 수 있게 정리해줘.
```

## 변경 파일 목록
- `src/app/page.daytrade.us/api.py`
  - `us_live_status`, `us_daily_log`, `us_verify_runtime`, `us_model_ranking`에 TTL 캐시와 degraded fallback을 추가
  - 미장 랭킹 응답에 전략 요약/진입/청산 설명과 생성 시각을 포함
- `src/app/page.daytrade.us/view.ts`
  - 초기 로딩을 1차(상태/일지)와 2차(검증/랭킹)로 분리
  - 종목 변경 시 불필요한 전체 재계산을 제거하고 상태/검증만 갱신
  - 랭킹 수동 새로고침과 전략 선택 정보 접근자를 추가
- `src/app/page.daytrade.us/view.html`
  - 백그라운드 로딩 안내, 랭킹 메타 정보, 랭킹 수동 갱신 버튼 추가
  - 각 전략의 요약/진입 규칙/청산 규칙을 보는 알고리즘 설명 섹션 추가

## 추가 메모
- 실제 삭제 가능한 중복 파일은 확인되지 않았다. 기존 build/bundle 산출물과 국장 페이지 내부 US 잔존 코드는 런타임/라우팅 영향 확인 없이 제거하면 회귀 위험이 커서 이번 작업에서는 삭제 대신 중복 호출 경로와 무거운 초기 요청을 정리했다.
- 현재 저장된 미장 `live_state`/`runtime_logs_us` 기준으로는 실매수·실매도 이력이 거의 없고 최근 로그 7건이 모두 `HOLD`라서, 현 미장 모델은 아직 “실사용 가능” 판정보다는 검증 단계로 보는 편이 타당하다.
