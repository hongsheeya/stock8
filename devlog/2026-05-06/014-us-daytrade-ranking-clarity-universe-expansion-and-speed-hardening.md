# 미장 단타 랭킹 의미 명확화, 후보 유니버스 확장, 로딩 추가 단축

- **ID**: 014
- **날짜**: 2026-05-06
- **유형**: 기능 추가

## 작업 요약
미장 단타 화면에서 랭킹 숫자가 단순한 번호처럼 보이던 문제를 `랭킹 N위` 형태로 명확히 바꾸고, 승률/수익률/MDD 기준의 실거래 품질 경고를 추가했다.
또한 기존 미장 후보가 정적 화이트리스트에 묶여 있던 이유를 화면에서 설명하도록 하고, 기본 후보군을 확장했으며, 심볼 검색으로 화이트리스트 밖 종목도 바로 조회할 수 있게 보강했다. 초기 진입 시에는 랭킹을 자동 계산하지 않도록 바꿔 미장 페이지 체감 로딩을 더 줄였다.

## 원문 요청사항
```text
1. 미장 단타 알고리즘 옆에 숫자는 뭘 의미하는거야. 저렇게 있으면 뭔지 아무도 모르잖아
2. 종목들 저거말고도 급등주나 더 좋은 종목들 많은데 저것들만 있는 이유가 뭔데
3. 오늘밤부터 제대로 작동하는지 제대로 검증들어가봐
4. 아직도 미장은 로딩시간이 너무 오래걸려
5. 승률이 3퍼면 안하는게 낫지 않냐?
```

## 변경 파일 목록
- `src/portal/trading/model/struct/daytrade.py`
  - 미장 기본 후보군을 대형주/ETF/모멘텀 종목 중심으로 확장
  - 미장 후보 유니버스가 왜 화이트리스트 기반인지 설명하는 `us_candidate_universe_policy()` 추가
- `src/app/page.daytrade.us/api.py`
  - `us_search_symbols()` 추가로 화이트리스트 밖 심볼 직접 검색 지원
  - `us_bootstrap()` 응답에 `universe_policy` 포함
  - `us_model_ranking()`에 실거래 권장 여부 품질 게이트(`tradable`, `quality_note`, `quality_gate`) 추가
- `build/src/app/page.daytrade.us/api.py`
  - 위 API 변경을 런타임 빌드 파일에도 동기화
- `bundle/src/app/page.daytrade.us/api.py`
  - 위 API 변경을 번들 런타임 파일에도 동기화
- `src/app/page.daytrade.us/view.ts`
  - 초기 화면 진입 시 랭킹 자동 계산 제거
  - 상태/일지/검증 백그라운드 로딩 구조 재정리
  - 심볼 검색 및 검색 결과 적용 로직 추가
- `src/app/page.daytrade.us/view.html`
  - `#1` 형식을 `랭킹 1위`로 명확화
  - 화이트리스트 유니버스 설명과 수동 심볼 검색 UI 추가
  - `승률 3%면 비권장` 성격의 품질 경고 메시지 추가
  - 랭킹을 수동 실행하도록 변경하여 초기 체감 로딩 단축

## 추가 메모
- 현재 저장된 `runtime_logs_us.json`과 `live_state.json` 기준으로는 최근 미장 표본이 매우 적고 대부분 `HOLD`이므로, 낮은 승률 수치가 보이면 자동 실거래를 권장하지 않는 방향으로 해석하는 것이 맞다.
- 오늘 밤 운용 검증은 새로 추가한 품질 경고/실행 검증 패널 기준으로 재확인하도록 구조를 정리했다. 다만 실제 장중 체결 검증은 시장 개장 후 실데이터가 들어와야 최종 판정 가능하다.
